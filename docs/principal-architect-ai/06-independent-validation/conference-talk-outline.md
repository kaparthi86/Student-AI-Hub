# Conference / Meetup Talk Outline

**Title:** Building a Student AI Coach: Response Contracts, Honor Codes, and Cost-Aware Inference  
**Length:** 25 minutes + 5 Q&A  
**Audience:** AI engineers, edtech builders, principal architects

## Outline

1. **Hook (2m)** — Generic chat fails schoolwork; brand confusion; submission-ready answers.  
2. **Product wedge (3m)** — My Student Coach: Ask / Code / Notebook only.  
3. **Response contracts (5m)** — Answer-first; strip markdown noise; Guide/Quiz honor modes.  
4. **Grounding (4m)** — Notebook “Not in document”; optional live web sources.  
5. **Architecture (5m)** — HF Router, SSE, abort/stop, completion cache, voice speak-early.  
6. **Economics (3m)** — Cache + voiceMode token caps; measure $/study turn.  
7. **Close (3m)** — PWA→TWA path; what we’d do with realtime voice next.

## Abstract (150 words)

```
[[DRAFT]] Students increasingly use general-purpose AI for homework, but generic chat
optimizes for fluency—not learning. My Student Coach is a focused study product that
combines answer-first response contracts, honor-code tutoring modes, document-grounded
notebook workflows, and a cost-aware Hugging Face inference path with caching and a
conversational voice loop. This talk shares the architecture and product decisions
behind shipping that system as a principal-level AI engineer/owner.
```
